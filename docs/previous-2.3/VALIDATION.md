## 关键验证点

### 原工程与打包

`src/engine.js` 与 `build.py` 的 SHA-256 和上传原件一致。四份 JavaScript 均通过 Node 语法检查；实际执行原 `python build.py` 后，五个模板标记均被替换，没有外链脚本或网络资源依赖。

本版源自当前可读取的原始上传工程，不是无法取得的历史 2.2 包的字节级增量。本次没有把旧版/实验室文件冒充为正式构建。

### 武库与商店

验证十二角色一武器 I 级开局、正常 6 槽/道具 8 槽上限、固定槽角色、装备硬约束、重复占槽、明确合成、满槽付费合成、不同型号/等级禁止合成、终式限制、拆除确认/取消、最后一把保护、实付成本累计与拆除防套利。

锁定报价跨波保留；全锁定不扣刷新费；定向材料匹配型号/改装/等级；连续两轮未匹配保底不会覆盖锁定商品；高等级定向不被自然解锁波次误拦截。

核心第三颗购买必须选择替换，交易原子扣款，不重复收钱；按付款后余额计算金库伤害，不更改旧报价。战利品只在商店安装，自动拾取不会默默加入负属性。

### 十二核心与数值边界

逐一验证低血、第三刀、第三发、三件工程、三元素同体、三目标爆炸、余额、真实拾取、实际护甲减伤、连续无伤、冲刺穿越三敌、近身精英击杀等条件，以及相应的真实伤害、治疗、伴随机、护盾或时间变化。

额外验证：

- 无条件提前触发不会生效；高频事件有全局间隔或容量限制。
- 核心衍生攻击不继续触发核心、不吸血；核心衍生精英击杀不会触发寄生治疗，普通持续伤害的近身精英击杀可以。
- 过量伤害不会制造额外吸血；致命伤害与嵌套爆炸不产生负伤害统计。
- 自伤不能给护甲核心充能，波末素材回收不能给拾荒核心充能。
- 护甲减伤/闪避最大 60%，负护甲增加承伤，吸血鬼正回复锁零但负回复仍是代价。
- 同家族同等级的六种改装共 **600 组有向比较**没有全维度支配。比较包括自伤、减速等成本，不代表跨家族、跨战斗情境的数学最优性证明。

### 实际武器与近战

120 条武器配置全部通过实际伤害检查。六把太刀具有分别推进的出刀次数、目标/命中记录；背后目标不因同在半径内而自动受伤，拆除后相关挥刀/部署记录清除。浏览器使用生产渲染器绘制六刀与实际触发的折镜核心，不是额外绘制的效果图。

### 首领、死亡与界面

检查首领三类地面预警、第二阶段与场地变化；冲锋前摇、远程保持距离；精英必掉道具、爆炸桶预警。真正致命的超载自伤进入死亡界面并保留命名来源；负回复死亡也有明确来源。

检查 16 项属性展开来源、三选一键盘选择、弹窗焦点循环、武器搜索/类型/伤害来源、核心条件/代价/余额对比。HUD 高度 16px、数值不小于 20px；遮住左上角后的截图仍有中央生命条/数字、能量环及边缘濒危反馈。**没有用自动化声称通过色觉用户研究或死亡原因识别率研究。**

### 触控与视口

检查 320×740、390×844、932×430。商店与详情无横向溢出、底部购买区在可视范围。用 Chromium CDP 触摸事件走真实 pointer dispatch/capture，验证模拟摇杆、反向、第二指冲刺、独立抬指、取消、旋转清方向、手指滑动商店与详情、点击固定结算按钮。不是只用 JavaScript 给摇杆变量赋值。

## 长流程与平衡证据

测试策略为固定的 16 方向局部避险、基础属性打分、有限刷新、遇到合适核心会存钱。它不是熟练玩家，也不会证明最优构筑。模拟不把渲染速度算作真人游玩时长。

| 角色 | 模式 | 抵达波次 | 结果 | 击杀 | 交易数 | 核心 |
|---|---|---:|---|---:|---:|---|
| street | 非无敌 | 11 | 死亡 | 561 | 14 | time |
| dancer | 非无敌 | 10 | 死亡 | 454 | 12 | 无 |
| engineer | 非无敌 | 12 | 死亡 | 553 | 10 | time, hive |
| elemental | 非无敌 | 11 | 死亡 | 543 | 13 | time |
| street | 无敌，仅验证流程 | 20 | 完成20波 | 2465 | 25 | time |

无敌样本有真实敌人、交易、首领和波次计时，完成了完整 20 波，但不会因生命伤害失败。其用途是确认状态链、经济交易和终局解锁能走通，**不能作为正常难度可以稳定通关的证据**。

非无敌样本均在中期失败。这说明中期存在压力，不代表真人首通率为 0%，也不能倒推出目标 30% 已实现。需要真人进行各流派、经济取舍和精英/首领可读性测试后进一步调参。

规定战斗时间合计 815 秒（13:35）。实际总时长还包含商店、升级、顿帧、首领延长；**15–20 分钟平均局时与约 30% 首次通关率仍未实测确认。**

## 对原验收标准逐项说明

| 标准 | 结论 |
|---|---|
| 第一波一把武器、不是必死开局 | 一把武器已验证，48 个非无敌首波样本存活；“吃力但合适”仍需真人评价 |
| 20 波、15–20 分钟、首通约 30% | 20 波状态链与规定计时已验证；真人局时及成功率未验证 |
| 两局构筑可明显区分 | 12 角色硬约束、9 类套装、12 核心及随机商店已实现；不保证随机结果绝不相同 |
| 无全维度最强改装 | 同族同等级改装的 600 个有向比较通过；不是跨场景平衡定理 |
| 商店有买/存、武器/道具取舍 | 交易、成本、槽位、定向、锁定、核心替换均验证；主观有趣程度待实玩 |
| 升级至少一项负代价 | 200 次抽样通过，选项去重，无白送武器 |
| 遮住左上角仍有生命档位信息 | 实际渲染截图通过，中央/边缘信息存在；未进行人群识别率研究 |
| 死亡原因明确 | 致命来源及最近八秒记录已实现并测试；真人理解速度待实玩 |

## 环境、未验证项与重现

图形测试使用 Linux Xvfb 下 Chromium + ANGLE/SwiftShader。不是实体手机。为避免软件 GL 持续占用影响无关 UI 测试，渲染检查之间暂停绘制，但保持生产输入/模拟的真实动画循环；单独调用的绘制仍使用完整原始管线。没有据此发布 FPS 跑分。

最终产物原文通过 `page.set_content` 进入断网上下文，**没有验证 `file://` 双击打开**，也没有通过 HTTP 服务器替代后宣称本地打开已通过。游戏本身不需要服务器；特定文件管理器的预览限制需要在目标设备确认。

未验证：iOS Safari、Android 实体设备、不同 GPU 的帧率/发热/续航、音频听感、真人色觉友好、长时间浏览器挂起恢复、真人流派强度与通关率。

```sh
python build.py
node tests/sim_checks.js
xvfb-run -a python tests/verify.py
node tests/long_runs.js
xvfb-run -a python tests/render_models.py
```

回归期间发现过测试定位器重复命中隐藏 HUD、测试误写死亡状态名，以及把 CDP“释放触点”误当作“剩余触点”的测试错误，均已修正。早期持续软件绘制还导致过测试超时；最终报告来自停止无关后台绘制后的完整成功运行，不混入未完成会话。
