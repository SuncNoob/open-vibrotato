## 打开游戏

将 `NeonSpud.html` 保存到本地，使用支持 WebGL2 且允许本地脚本的桌面浏览器打开。
游戏的脚本、样式、程序化模型、音效和图标全部内置，不需要服务器、第三方运行库或 CDN。
聊天附件预览不一定允许执行游戏，请使用浏览器打开 HTML 本身。

当前自动化环境禁止 `file://` 导航；离线兼容检查使用原样构建产物载入断网浏览器。
实体手机、iOS Safari、系统文件管理器打开 HTML 的行为尚未实测。

## 这版重点

### 同款近战不再挤成一把

- 近战按装备实例而非武器型号分配独立悬浮挂点。两把对向、四把四向，六把和八把等间隔环绕。
- 混搭枪械时，刀的方位仍按近战数量分配；两把刀不会因为另外四把枪而挤在一起。
- 角色转头不会让整组刀跟着转向同一敌人。敌人包围时，优先攻击各自方位，并避免抢同一目标。
- 同一个 Boss 可以被多刀合击，但每把刀保留不同起点、分层高度与交替挥砍方向；不是强制让刀背对唯一目标。
- 动作包含前摇、实际刀锋扫过、收刀回位。收刀连续插值回到自己的悬浮方位，不停留在目标方向。
- 保留 2.3 的三段重斩与折镜刀匣双回响。核心衍生攻击仍不递归触发核心、不吸血。
- 采用到期优先的独立出刀调度，高攻速时缩短错峰间隔，避免前排槽位让后排刀一直等不到出手。

伤害根据各自挂点的扫掠方向判定，同时限制在原本的角色中心射程内。
刀光不会制造额外范围伤害，伤害、冷却、售价、等级和核心倍率没有在本轮上调。

### 从 2.2 继承并增强的表现

独立槽位配色、钢质刀脊、发光刃口、护手标记、短弧残影、分层破风与金属命中音。
传说刀统一保留橙色，普通同款刀用不同槽位色和握柄刻度区分。
增强弹道亮芯、短拖尾、枪口闪光与光束芯线，不把整张场景曝光推白。

设置里新增“武器光效：增强 / 简洁”。手机自动降低拖尾层数与数量。
增强开关不改变伤害、经济或构筑随机数。关闭后仍保留实体武器和基本攻击提示。

### 右上角全屏

按钮常驻在菜单、战斗、商店和详情弹窗上方。点击进入 / 退出，桌面也可按 **F** 切换。
按钮状态跟随浏览器实际全屏状态，不以请求发出就当作成功。
全屏失败或不支持时显示提示；切换时清除残留移动输入。
手机按钮至少 46 × 46 CSS 像素，考虑安全区，并为血条、波次和详情购买按钮预留位置。

全屏由浏览器提供，受版本、嵌入页面权限和用户操作要求限制；不承诺每种手机浏览器都支持。

## 保留的 2.3 游戏系统

正式开局依然只有一把 I 级武器；12 个角色、20 波、危险等级、核心系统、角色模型、
升级、商店、装备拆除、满槽付费合成、定向材料与保底、套装、自动拾取、双指操作和死亡记录继续保留。
本轮没有重做经济，没有把工程回退成 1.0，也没有移除 2.3 核心机制。

## 修改与重新打包

```sh
python build.py
```

输出 `NeonSpud.html`。`src/engine.js` 与 `build.py` 对两份上传工程均保持逐字节一致。
`src/weapons.js`、`weapon-catalog.json`、`item-catalog.json` 与上传的 2.3 保持逐字节一致。

开发时的验证依赖为 Node.js、Python、Playwright、Chromium、Pillow，以及 Linux 下的 Xvfb；
这些依赖不随游戏运行。

```sh
python tests/verify.py --simulation-only
xvfb-run -a python tests/verify.py
```

`tests/verify_base.py` 保留 2.3 的完整回归；
`tests/starform_checks.js` 增加悬浮、方向、调度和光效隔离检查；
`tests/starform_browser.py` 检查实际 WebGL 绘制、全屏与手机布局，并生成截图和动图。

## 关于截图和测试配装

动图与多刀截图使用固定高血量目标和明确标注的测试配装，由游戏的实际 WebGL 渲染器生成。
它们不是正式开局配置、真人实战录像或帧率评测。正式开始依然只有一把武器。

变更依据见 `CHANGELOG.md`，测试结果及未验证事项见 `VALIDATION.md`。
`docs/previous-2.3/` 仅为上传版本的历史资料。
